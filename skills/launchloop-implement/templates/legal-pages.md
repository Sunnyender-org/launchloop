# 法务页骨架（L03）

> **这不是法律意见。** 下面只是四个页面的结构和必须回答的问题。正文由你写或用 Termly / iubenda / GetTerms 等生成器生成，上线前请懂法律的人看一眼。本 Skill 不生成有法律效力的条款文本。

四页都要：从 footer 可达；链接文字含 `Terms` / `Privacy` / `Refund` / `Cookie`（或 条款 / 隐私 / 退款 / Cookie）；有"最后更新日期"；有联系方式。

## /terms — 服务条款

必须回答：
- 服务方是谁（公司全名 / 个人）、注册地、联系邮箱
- 谁可以用（年龄、地区限制）
- 账户责任：密码、不得共享、我们何时可以封号
- 付费：价格在哪看、按什么周期扣、自动续费怎么取消、税费谁承担
- **如果用 MoR（Lemon Squeezy / Paddle / Creem）**：写明"付款由 X 作为 Merchant of Record 处理，购买合同的对方是 X"，并链接到 X 的条款
- 用户内容归谁、你有什么使用授权
- AI 生成内容的免责：输出可能不准确，用户自行判断
- 服务可用性：不保证 100%，可能变更或停止
- 责任上限（通常为过去 12 个月付费金额）
- 争议解决与适用法律
- 条款变更如何通知

## /privacy — 隐私政策

必须回答：
- 收集什么：账户信息、使用数据、上传内容、支付信息（通常不经手卡号，由支付平台处理）、Cookie
- 用来做什么、法律依据（GDPR 用户需要）
- **子处理方清单**：托管（Vercel / Cloudflare）、数据库（Supabase）、支付（Stripe / LS）、邮件（Resend）、分析（Plausible / PostHog）、AI 提供方（OpenAI / Anthropic）——每个写名字和用途
- **用户内容是否被送到 AI 提供方，是否用于训练**：明确回答
- 保留多久、如何删除账户和数据
- 用户权利：访问、更正、删除、导出、撤回同意
- 跨境传输
- 儿童数据
- 联系方式

### 中国路径额外段落（用户在中国大陆时）

- 依据《个人信息保护法》：单独列出收集的个人信息种类，敏感信息（手机号等）需**单独同意**
- 第三方 SDK 清单（与子处理方清单合并）
- 生成式 AI 服务标识：依据《生成式人工智能服务管理暂行办法》，说明服务使用了生成式 AI，输出内容为 AI 生成
- 未成年人保护条款
- 个人信息保护负责人联系方式

## /refund — 退款政策

必须回答：
- 多少天内可退、什么条件（未使用 / 部分使用）
- 数字商品与订阅的差异；按比例退还是不退当期
- 怎么申请（邮箱 / 后台按钮）、多久到账
- **MoR 覆盖声明**：如果用 Lemon Squeezy / Paddle，写明"最终退款决定遵循 X 的政策"，因为 MoR 有权在你写"不退款"的情况下仍然退款以避免拒付
- 试用转付费前是否会提醒

**这一页的内容必须和支付后台设置一致**（`LAUNCHLOOP.md` 门 2 硬门槛）。

## /cookies — Cookie 说明（可并入隐私政策）

- 分类：必要 / 分析 / 营销
- 各自用了什么（名字、提供方、时长）
- 欧盟用户需要同意横幅；只用 Plausible 这类无 Cookie 分析可以省掉横幅，值得为此选型
